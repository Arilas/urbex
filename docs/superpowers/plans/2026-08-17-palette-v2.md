# Palette format v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement palette format version 2 as specified in [`docs/format/`](../../format/README.md), alongside version 1, with every one of its 289 rules bound to a test.

**Architecture:** Version 2 is a separate code path from version 1, not a dialect of it. A dispatching codec inspects `version` on the raw document and delegates; an `extends` chain may not cross versions, so the two compilers never meet. Version 2 decodes to a raw node tree, resolves every reference and operand at load, apportions sizes as exact rationals, and materialises one flat compiled entry per marker holding both states and traits.

Version 1 is deprecated. It stays loadable so existing packs keep working, but it is not the target of any new work: where the two would diverge, version 2's shape wins and version 1 adapts to it. The plan ends with the bundled pack converted to version 2, which is what makes version 1 removable in a later change.

**Tech Stack:** Java 21, Mojang DataFixerUpper codecs, JUnit 5, `com.networknt:json-schema-validator` 1.5.6, Fabric `DynamicRegistries`.

## Global Constraints

- **The specification is the contract.** Every behaviour comes from a numbered rule in `docs/format/palette/`. Do not invent behaviour; if a rule is missing, add the rule first and regenerate the conformance index.
- **Every rejection cites a `DIAG` identifier** from [`08-errors.md`](../../format/palette/08-errors.md). Tests assert against the catalogue entry, never a literal string.
- **Version 1 is deprecated and treated as dead code.** It is scheduled for removal from execution. Do not invest in preserving its behaviour, do not build dual code paths to spare it, and do not protect its output. Where version 1 and version 2 would need separate handling, write the version 2 path and adapt version 1 to it.
- **Goldens are regenerated, not preserved.** The five digest goldens (`digest.golden`, `digest-avoid.golden`, `digest-avoid-modes.golden`, `digest-features.golden`, `digest-rail.golden`) move whenever generation changes. Re-pin them by deleting the file and running twice to confirm the two runs agree — never by editing a value until it matches. Say in the commit message which change moved them and why.
- **Version 1 keeps loading until it is removed.** `VER.001` still holds: a file with no `version` decodes by the version 1 rules, because every shipped pack is version 1 today. `VER.004` still holds too — do not make version 1 stricter on the way out.
- **No static mutable state** in compilation — `LOAD.031`.
- **Diagnostics are collected, not thrown** — `LOAD.004`, `DIAG.903`. A failing palette must not abort the compilation of other assets.
- **Every `REJECT` rule is enforced at load** — `LOAD.010`. Nothing is deferred to generation.
- Java package for the new format: `dev.krona.urbex.format` for machinery reusable by other registries, `dev.krona.urbex.format.palette` for palette-specific types.
- Run `./gradlew test` at the end of every task. A task is not done while any test fails.

`Versioned.dispatch` inspects the raw `Dynamic` before delegating, exactly as `RetiredKeys.reject` does — that is the pattern `VER.003` requires and it already exists in the codebase to copy from.

```java
public static <T> Codec<T> dispatch(String context, Map<Integer, Codec<? extends T>> byVersion) {
    return new Codec<>() {
        @Override public <O> DataResult<Pair<T, O>> decode(DynamicOps<O> ops, O input) {
            int version = new Dynamic<>(ops, input).get("version").asInt(1);
            Codec<? extends T> codec = byVersion.get(version);
            if (codec == null) {
                return DataResult.error(() -> Diag.DIAG_001.message(context, version));
            }
            return codec.decode(ops, input).map(p -> p.mapFirst(v -> (T) v));
        }
        // encode delegates to the codec matching input.formatVersion()
    };
}
```

`PaletteDefinition` (version 1) is unchanged and simply gains `implements PaletteAssetDefinition` with `formatVersion() { return 1; }`. Its own `CODEC` keeps its `RetiredKeys.reject` wrapper, so version 1 keeps rejecting `inherit` and `parent` and keeps ignoring unknown keys.

- [ ] **Step 1: `Pointer.parse`**

Alias expansion is textual and happens before parsing — `REF.081`. So `parse` substitutes a leading `$name` from `imports` (with `$super` built in and unshadowable, `REF.082`), then reads what remains:

- contains `#` → `Fragment`; the part before `#` is an asset id, optionally prefixed `registry/`, defaulting to `palettes` (`REF.043`); the part after is an RFC 6901 pointer (`REF.042`)
- contains `:` → `Registry`
- otherwise → `Local`, and `REF.084` refuses a `/` or a leading `$`

An unknown alias is `DIAG.039` and must not fall back to `Local` — `REF.083`.

- [ ] **Step 2: `NodeResolver`, the topological pass**

`REF.031`: one topological sort, not a fixpoint loop. Build the reference graph over every `$defs` name, every registry definition and every marker, then resolve in dependency order. A cycle is `DIAG.032` naming every node in it, in declaration order from the node reached first — collect the stack, do not let it become a `StackOverflowError`.

Order within one node, from `REF.003`, `REF.004`, `REF.051`, `REF.052`:

1. resolve `$ref`'s target
2. filter it by `$only` or `$without` (both present is `DIAG.035`)
3. apply the referring node's own keys over the result, key by key
4. merge `traits` by id, replacing whole

`$spread` is expanded before any of that, wherever a list appears — `choices` and each of the four placement lists. `REF.072` means a spread element carries no other key; `REF.071` refuses a pointer that does not name a list.

`$super` resolves against `ResolutionScope.inherited`, which Task 4 populates from the `extends` chain. Until then it is always empty, so `DIAG.036` fires — that is correct behaviour for a file with no `extends`, and Task 4's tests cover the other branch.

- [ ] **Step 3: The `definitions` registry**

`DefinitionAssetDefinition` is one `RawNode` plus `version`, `extends` and `$imports`, and no `palette` — `REF.014`, `REF.018`. Register it as `urbex:definitions`. It replaces `variants` for version 2 palettes; `variants` stays registered and untouched for version 1.

- [ ] **Step 4: Completeness**

`MODEL.080`–`MODEL.082`: after resolution, a node in a marker position, a `choices` entry or a socket candidate must have a kind and that kind's required keys, or `DIAG.011` names both the marker and the definition it came from. A `$defs` entry need not.

  - `Apportion.slots(List<Fraction> shares, int slotCount)` → `int[]`, where `Fraction` is an exact rational

- [ ] **Step 1: Exclusion, before apportionment**

`WEIGHT.020`–`WEIGHT.023`: `when` is evaluated once, at load, against mod presence and pack presence — both already implemented in `ReferenceProvider`. `WEIGHT.030`, `WEIGHT.031`: an absent block drops, after `when`. `WEIGHT.024`, `WEIGHT.032`: everything excluded is `DIAG.043`, reporting how many went each way.

`WEIGHT.021`: a removed `share` is redistributed to the `weight` choices, or proportionally among the remaining shares if there are none.

- [ ] **Step 2: Sizes, checked after expansion**

`WEIGHT.005` is the subtle one and needs its own test: every size rule is evaluated on the list as it stands after `$spread` expansion and exclusion, never on what was written. A file writing one `share` and taking the rest of its list from a spread is correct and must not be refused.

`WEIGHT.013`: more than one `rest`, or a `rest` beside a `weight`, is `DIAG.041`. `WEIGHT.014`: shares reaching 1 with a weight present, or not reaching 1 without one, is `DIAG.045` — and `WEIGHT.019` requires that message to name the written and inherited totals separately.

- [ ] **Step 3: Exact rationals, one materialisation**

`WEIGHT.052`: walk the resolved tree accumulating exact fractions, resolve `rest` against its own level, then materialise 128 slots once at the root. Use `long` numerator and denominator with reduction, not `double` — the specification says exact and a test will hold it to that.

`WEIGHT.060`–`WEIGHT.062`: largest remainder, ties to the lowest index, every slot assigned, and a choice whose exact share rounds below one slot still gets one with the deficit taken from the largest. `WEIGHT.063`: more than 128 choices is `DIAG.044`.

`WEIGHT.053` is the invariant test worth writing carefully: for a nested tree, the compiled distribution equals the flattened equivalent to within one slot per choice.

- [ ] **Step 4: Selection is position-addressed**

`WEIGHT.040`–`WEIGHT.043`: reuse `Rng.indexAtPos` with `Rng.Purpose.PALETTE` and the marker keyed into the seed, exactly as version 1 does. `WEIGHT.015` gets an explicit test: shuffling a list's declaration order does not change its distribution.

- [ ] **Step 5: Verify and commit**

```bash
./gradlew test && git diff --exit-code -- '*.golden'
git commit -am "feat(format): apportion palette v2 sizes as exact rationals"
```
